## Recommend an article

Use a [GitHub Issue](https://github.com/deepfurry/gopher-atlas/issues) to recommend quality Go writing or report inaccurate metadata, broken links, or topic organization problems.

Include a title, source URL, external author, publisher, source date, language, difficulty, short summary, editorial rationale, suggested rating, and relevant tags. The source publication date and the date added to GopherAtlas are different.

Titles and “Read full article” use the main `sourceUrl`. Use `originalUrl` for an original reference or translation source, and related links for multi-part articles. Explain why the article is useful; do not copy its full text.

## Editing and review

Content is maintained in the Chinese Admin. After account approval, editors create their own curated articles or learning notes, save drafts, and submit them for review. Reviewers read an immutable Revision and request changes or approve it. Administrators can publish directly.

Ratings are `S+ / S / A+ / A / B+ / B / C+ / C`; difficulty is beginner, intermediate, or advanced. Reuse short, clear tags. Administrators arrange Topics using curated articles only; the recommended section is the beginning of the complete ordered list.

## Learning Notes

Notes are original Markdown writing. Add a meaningful title and summary, choose a byline and group, and set the reading order. The group and article slugs form the permanent URL; change them carefully.

Notes in a group share its name, description, and order. Select an existing group or explicitly define a new one. Start body headings at H2. Lists, tables, tasks, footnotes, and fenced code with a language are supported. Raw HTML, scripts, iframes, and Markdown frontmatter are not allowed.

Upload images to the asset library, then insert immutable URLs with useful alt text. Do not embed third-party images. Draft preview does not publish; the Public build changes after a selected Revision is published.

## Contribution standards

- Explain concrete problems, principles, and trade-offs.
- Favor useful engineering insights.
- Add context for older articles that remain valuable.
- Respect copyright, attribute sources, and avoid duplicates.
- Follow the repository README and unified checks for code contributions.

When unsure, start an Issue. Public comments and reactions use GitHub Discussions and remain separate from editorial review.
