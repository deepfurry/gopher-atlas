## 推荐精选文章

欢迎通过 [GitHub Issue](https://github.com/deepfurry/gopher-atlas/issues) 推荐高质量 Go 技术文章，或指出信息错误、失效链接和不合理的话题编排。

请提供标题、原文 URL、外部作者、来源平台、原文日期、语言、难度、简洁摘要、收录理由、建议评级和相关 Tag。原文日期与本站收录时间是不同的时间，不要混用。

标题与“阅读全文”指向主入口 `sourceUrl`。译文或参考材料可填写 `originalUrl`；系列文章可补充分段链接。收录理由应说明工程价值与适用场景，不要复制外部正文。

## 编辑与审核

正式内容通过中文 Admin 维护。维护者审核账号后，编辑可以创建自己的精选文章或学习随笔，保存草稿并提交审核。审核员阅读不可变 Revision，要求修改或批准；管理员可直接发布。

评级允许 `S+ / S / A+ / A / B+ / B / C+ / C`，表示阅读优先级；难度使用入门、进阶、高级。Tag 尽量短小明确，复用现有词表。Topic 由管理员编排，只包含精选文章，推荐区的条目位于完整清单的前部。

## 学习随笔

学习随笔是原创 Markdown 博客。使用有意义的标题和摘要，选择署名与分组，设置组内顺序。分组标识 `groupSlug` 和文章 `slug` 参与永久 URL，应慎重修改。

同一分组的名称、说明与排序必须一致。新文章可选择已有分组，或显式填写新分组。正文从 H2 开始，支持列表、表格、任务清单、脚注和标明语言的代码块；不要使用 raw HTML、脚本、iframe 或 Markdown frontmatter。

图片先上传素材库，再插入带有 alt 文本的不可变 URL。不要直接引用第三方图片。预览不会发布草稿；正式发布选定的 Revision 后，Public build 才会更新。

## 贡献标准

- 讲清具体问题、原理和取舍。
- 优先推荐对实际工程有启发的材料。
- 对较旧但仍有价值的文章补充背景。
- 尊重版权，标明来源，不重复提交已收录内容。
- 代码贡献使用 pnpm 和仓库统一检查；具体流程见仓库 README。

如果不确定内容是否适合收录，欢迎先开 Issue 讨论。公开评论与 Reactions 使用 GitHub Discussions，不影响内容的编辑和审核流程。
